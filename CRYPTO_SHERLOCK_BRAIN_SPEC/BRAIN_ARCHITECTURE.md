# BRAIN_ARCHITECTURE — архитектура CRYPTO SHERLOCK BRAIN

Версия: 0.1.0

## Цель
Создать исследовательскую систему, которая изучает рыночные данные, самостоятельно обнаруживает кандидатов в закономерности, формирует проверяемые гипотезы, проводит эксперименты, оценивает неопределённость и сохраняет результаты. Это не обещание сверхразума или доходности.

## Слои системы

### 1. Data Foundation
- Проверенные исторические свечи и позднее дополнительные источники.
- Каноническая модель свечи, UTC timestamps.
- Контроль пропусков, дублей, OHLCV, неполных свечей и происхождения данных.
- Read-only доступ к исходным CSV и sherlock_market.db.
- Отдельное хранилище признаков, исследований и результатов.

### 2. Market Perception
- Свечные, ценовые, объёмные и волатильностные признаки.
- Структура максимумов/минимумов.
- Режимы: trend, range, high volatility, transition, insufficient data.
- Межтаймфреймовое согласование только по закрытым старшим свечам.

### 3. Research & Discovery
- Поиск похожих фрагментов разной длины.
- Кластеризация, поиск последовательностей и аномалий.
- Генерация кандидатов-гипотез.
- Отдельные стратегии, включая сохранённую пятиэтапную формацию.

### 4. Experiment & Validation
- Предварительная фиксация гипотезы и критериев.
- Хронологические train/validation/test.
- Walk-forward evaluation.
- Baselines, комиссии, проскальзывание и при необходимости funding.
- Контроль множественных сравнений и переобучения.

### 5. Learning & Model Management
- Обучение на причинно доступных признаках.
- Калибровка вероятностей.
- Реестр моделей и наборов данных.
- Champion/Challenger, drift monitoring, откат.

### 6. Sherlock Core — оркестратор
Core — центральный координатор, а не магическая единая нейросеть. Он ставит задачи, проверяет готовность данных, запускает модули, собирает результаты с provenance, выявляет противоречия, назначает дополнительные проверки и формирует объяснимый отчёт. Он не превращает мнение отдельного модуля в доказанный факт.

### 7. Interfaces
Desktop — основной локальный интерфейс; Web/API и Mobile — клиенты одного ядра. Аналитическая логика не дублируется в интерфейсах.

## Поток
Market Data → Validation → Feature Store → Discovery → Hypotheses → Experiments → Validation → Knowledge Memory / Model Registry → Sherlock Core → Reports / Paper Trading.

Обратная связь: Forecast → Outcome Tracker → Evaluation → Learning / Drift Monitoring.

## Память
Разделять raw data, feature data, research memory, model registry и forecast ledger. Каждая запись содержит версии и происхождение.

## Режимы
RESEARCH, BACKTEST, PAPER. LIVE запрещён в текущем объёме; не реализовывать API отправки реальных ордеров.
